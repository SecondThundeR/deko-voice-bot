# Deko Voice Bot

Бот для отправки реплик [deko](https://liquipedia.net/counterstrike/Deko) от лица пользователя через [Inline Query](https://core.telegram.org/bots/features#inline-requests)

Бот позволяет просматривать весь список реплик, доступных в базе данных, а также искать нужные с помощью текстового запроса

> [!NOTE]
> Ссылка на "боевого" бота: <https://t.me/dekoquotes_bot>

## Используемые технологии

- Бот построен на [Node.js](https://nodejs.org/) с использованием [TypeScript](https://www.typescriptlang.org/)
- В качестве библиотеки для взаимодействия с Telegram Bot API используется [grammY](https://github.com/grammyjs/grammY/)
- Бот и база данных работают на хостинге [Railway](https://railway.app/). Данные управляются с помощью [Drizzle ORM](https://orm.drizzle.team/)
- Строки сообщений и другого текста бота находятся в [Fluent](https://projectfluent.org/) формате и обрабатываются с помощью плагина [@grammyjs/i18n](https://grammy.dev/plugins/i18n/)
- Менюшки работают через плагин [@grammyjs/menu](https://grammy.dev/plugins/menu) и интерактивные диалоги через плагин [@grammyjs/conversations](https://grammy.dev/plugins/conversations)
- Конвертация аудио и операции с дампами базы вынесены в небольшой приватный [Hono](https://hono.dev/) сервис

## Как работает бот

В документации Telegram Bot API описана возможность отправки голосовых сообщений с помощью Inline двумя способами:

- Передача `file_id` голосового сообщения
- Передача ссылки на .ogg файл в удаленном хранилище

Во времена первой версии бота, реплики находились на Google Drive, откуда потом доставались прямые ссылки на каждую реплику и отправлялись в Telegram. В дальнейшем была добавлена возможность отправки реплик в формате .mp3 в чат с ботом для их автоматической конвертации и кеширования на сервере Telegram (в базу данных сохранялся только `file_id`)

> [!WARNING]
>
> Начиная с версии 3.6.0, возможность хранения голосовых реплик в удаленном хранилище была удалена в связи с большим потреблением сетевого трафика и потенциальных проблем с безопасностью
>
> Если вы самостоятельно хостите бота, то перед обновлением замените все удаленные реплики на локальные через `/voices` -> Выбрать нужную реплику -> Нажать кнопку "Заменить ссылку на файл" -> Скинуть в чат .mp3 реплики

Для правильного кеширования реплик, лучше создать отдельный чат с ботом (или можно не создавать и использовать личные сообщения с ботом) и отправлять все файлы реплик туда. Таким образом `file_id` будет стабильным и работать корректно для пользователей

## Как использовать исходники бота у себя

> [!TIP]
> tl;dr скачайте исходники, настройте базу данных, заполните необходимые переменные в `.env` и запустите удобным образом

Подробная инструкция по полной настройке бота теперь находится [здесь](https://github.com/SecondThundeR/deko-voice-bot/wiki/%D0%A1%D0%BA%D0%B0%D1%87%D0%B8%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5,-%D0%BD%D0%B0%D1%81%D1%82%D1%80%D0%BE%D0%B9%D0%BA%D0%B0-%D0%B8-%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA-%D0%B1%D0%BE%D1%82%D0%B0)

Пользовательские и conversation-сессии хранятся в памяти процесса до 24 часов с момента последнего изменения. После перезапуска бота открытые меню и незавершённые диалоги сбрасываются. Такая конфигурация рассчитана на одну реплику приложения

В webhook-режиме Telegram updates обрабатываются прямо HTTP-обработчиком без внутренней очереди и отдельных worker-процессов. Бот запрашивает только используемые типы updates: сообщения, callback query, inline query, выбранные inline-результаты и pre-checkout query

### Сервисы

Репозиторий состоит из двух запускаемых приложений:

- `apps/bot` сохраняет текущие команды и Telegram-интерфейс;
- `apps/api` — приватный Hono-сервис для конвертации MP3 через FFmpeg, экспорта, проверки и восстановления PostgreSQL.

Общий код не импортируется между приложениями относительными путями. Он разделён на workspace-пакеты:

- `@deko-voice-bot/backup` — формат, шифрование и PostgreSQL backup/restore;
- `@deko-voice-bot/contract` — маршруты и схемы ответов внутреннего API;
- `@deko-voice-bot/shared` — загрузка окружения и безопасное логирование ошибок.

Локально приложения запускаются двумя процессами:

```sh
pnpm dev:api
pnpm dev
```

Оба контейнера локально управляются одним Compose-файлом:

```sh
docker compose up --build
```

Compose запускает `apps/bot/Dockerfile` и `apps/api/Dockerfile`, ждёт healthcheck API-сервиса и передаёт боту внутренний адрес `http://api:3003`. PostgreSQL намеренно не включён в Compose: используется база из `DATABASE_URL`

#### Railway

Railway [не запускает Compose-файл напрямую](https://docs.railway.com/guides/docker-compose): каждый элемент `services` необходимо создать отдельным Railway service из одного GitHub-репозитория.

1. Создайте managed PostgreSQL и два сервиса `bot` и `api`.
2. Укажите Dockerfile Path `apps/bot/Dockerfile` для бота и `apps/api/Dockerfile` для API.
3. Передайте обоим сервисам `DATABASE_URL` как reference variable managed PostgreSQL и одинаковое секретное значение `API_TOKEN`.
4. Для API задайте `API_HOST=0.0.0.0` и `API_PORT=3003`, но не создавайте публичный домен.
5. Для бота задайте `API_URL=http://api.railway.internal:3003`. Публичный домен нужен только боту в webhook-режиме.

У Railway нет аналога `depends_on`, поэтому бот самостоятельно повторяет healthcheck до готовности API-сервиса. В production предполагается по одной реплике каждого приложения. Ключ `BACKUP_ENCRYPTION_KEY` передаётся только API-сервису

### Логирование

- `LOG_FORMAT=pretty` выводит компактные человекочитаемые логи и используется по умолчанию в development. В production по умолчанию используется `json`, который пишется напрямую в stdout без отдельного форматирующего worker-потока
- `LOG_COLORIZE=true` включает ANSI-цвета. Для Railway рекомендуется `false`, а для локального терминала — `true`
- `LOG_LEVEL` задаёт минимальный уровень логов. Для production рекомендуется `info`
- `USE_DEBUG=true` добавляет события получения и обработки Telegram updates, вызовы Bot API и HTTP-запросы. Эти события видны только при `LOG_LEVEL=debug` или `trace`

Для временной диагностики в production можно включить `LOG_LEVEL=debug` и `USE_DEBUG=true`, а после расследования вернуть `LOG_LEVEL=info` и `USE_DEBUG=false`

Уровни используются следующим образом:

- `info` — значимые операции, например платёж, возврат или экспорт базы данных;
- `debug` — начало и завершение обработчика, жизненный цикл update, методы Bot API, HTTP-запросы и обезличенные параметры inline-поиска;
- `warn` — повторные попытки и некритичные аномалии;
- `error` и `fatal` — окончательные сбои с очищенными сообщениями и stack trace.

### Резервные копии

Команда `/export` отправляет администратору только зашифрованные файлы `.dump.enc`. Для восстановления сначала запустите `/import`, затем отправьте файл и подтвердите операцию кнопкой. После подтверждения webhook быстро отвечает Telegram, а отслеживаемая фоновая операция включает режим обслуживания, дожидается завершения уже начатых обработчиков, отправляет аварийную копию текущей базы и выполняет восстановление. На время восстановления новые запросы не обращаются к базе данных

Обязательная для API-сервиса переменная `BACKUP_ENCRYPTION_KEY` содержит 32-байтовый ключ в base64. Создать его можно командой:

```sh
openssl rand -base64 32
```

Храните ключ в secrets окружения и отдельно от резервных копий. При утрате ключа расшифровать существующие копии невозможно. Перед ротацией ключа перешифруйте нужные старые копии либо сохраните прежний ключ отдельно. `BACKUP_MAX_SIZE_MB` задаёт максимальный размер импортируемого файла, `IMPORT_SESSION_TTL_MINUTES` — время ожидания файла и подтверждения в боте, а `API_IMPORT_TTL_MINUTES` — срок хранения уже проверенного файла в API-сервисе. Последнее значение должно быть не меньше первого

Для перевода старого plaintext-дампа в новый формат и для аварийной расшифровки без бота используйте:

```sh
pnpm backup:crypto encrypt backup.dump backup.dump.enc
pnpm backup:crypto decrypt backup.dump.enc backup.dump
```

Координатор импорта хранится в памяти процесса. Во время восстановления бот прекращает новые обращения к базе, закрывает свой пул соединений и возобновляет работу только после подтверждения от API-сервиса. Безопасная конфигурация предполагает одну реплику бота и одну реплику API-сервиса

### Добавление новых реплик

Реплики в боте можно добавлять с помощью команды `/newvoices` и заранее заготовленных .mp3 файлов. Команда остаётся в боте, а конвертацию в формат голосовых сообщений выполняет API-сервис
